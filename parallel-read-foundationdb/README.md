# Parallel ordered-read experiment

This is a warm native read prototype over a 100,000-member fixture using three local FoundationDB 7.3.77 processes on one host, one DC/region, triple SSD, with simulated distinct zones. It compares the existing facade operation, a raw sequential control, and depth-frontier parallel reads using stored subtree counts. Each timed operation was checked outside timing for IDs, full records, and continuation.

The packet includes the original `main.rs`, `compile.mjs`, `run.mjs`, original notes in `ORIGINAL-README.md`, result summary, JSONL benchmark output, full run metadata, and harness build-input record. This README adds archive provenance and scope details. Original source evidence is copied unchanged. Its metadata includes historical process IDs and command lines, not credentials. `run.mjs` has no embedded credentials, but rebuild/replay requires the old local FDB SDK/dependency artifacts and an isolated owned cluster. The `fdb.cluster`, stores, logs, and benchmark binary are excluded. The source uses absolute historical paths; they are provenance, not portable configuration.

Scope: 60 timed samples / 12 cases, checked outputs. No HTTP/auth, writes, mixed workload, cross-host or WAN evidence. The predicted added-latency figures are explicit assumptions, not measured RTTs. This packet is not a production layout decision.
